# Teach Old Dogs New Tricks

> *"Don't fix what's not broken."*

Portfolio managers write trade sheets by hand because it's fast. Retyping those sheets into spreadsheets is slow and error-prone. **TODNT** keeps the paper workflow and automates everything after it: scan a stack of handwritten trade sheets (PDF or image), and get back one CSV per sheet.

I built it solo during my co-op work term, as a desktop app for the firm's staff.

## How it works

1. **Find the grid.** Scans are never perfectly straight. `GridDetector` searches for the page rotation coarse-to-fine: it samples angles across ±1°, keeps the best region score, and narrows the interval until it's within 0.01°. It then sweeps brightness thresholds and tolerances to find the header and every row and column line. Each candidate grid gets a score (header height, grid size, line counts, slant consistency), and the vertical lines are taken as a median **consensus** across many passes, so one smudge can't throw the grid off.
2. **Cut out the cells.** Line intersections become a matrix of cell boxes, and each cell is cropped tight to its handwriting.
3. **Read the text.** Handwritten cells go through a **fine-tuned `microsoft/trocr-base-handwritten`** transformer, with beam search and a confidence score per cell. Printed headers use EasyOCR, and the results are snapped to the expected column names.
4. **Don't trust the model.** Every reading gets a confidence score from the beam search. In the review and labelling tool, cells are shaded by relative confidence, so the shakiest readings get checked first.

## Speed: CPU or GPU

TODNT runs on any office PC, but every pipeline that uses a model (converting sheets, the labelling tool's OCR pass, and training) moves to a CUDA GPU automatically when one is available, and runs many times faster there. On a CPU, reading a full sheet takes minutes; the demo video was recorded on a CPU-only machine, which is why its OCR waits are sped up. Training effectively needs a GPU.

## Making the model better over time

The base TrOCR model has never seen these traders' handwriting, so the app includes a **labelling tool**. Users correct cells in a GUI, and each correction is saved as a PNG with its ground truth embedded in the image metadata. `OCRResourceManager.train_tr_ocr` then fine-tunes a new model from the pooled labels.

- Trains with the Hugging Face `Seq2SeqTrainer`, with a seeded 85/15 train/validation split, and keeps the checkpoint with the best validation loss.
- Built to fit a **4 GB GPU**: gradient checkpointing, fp16, Adafactor, batch size 2 with 16 gradient-accumulation steps.
- Six fine-tuned model generations so far.

## Engineering details

- **Pipelines as generators.** Conversion streams events (`GridFoundEvent`, `PageDoneEvent`, …) so the GUI and the CLI share one code path and show live progress.
- **Self-describing config.** Every tunable lives in typed dataclasses with descriptions attached as field metadata. The GUI builds its settings panels from those descriptions automatically.
- **One-click install.** `run_app.bat` bootstraps [uv](https://github.com/astral-sh/uv), creates a pinned Python 3.14 environment, and installs dependencies. Non-developers just double-click it.
- **Documentation.** A full user guide, plus API docs for every module generated by a small Markdown generator I wrote.
